# ConnectIt

一個 WPF 桌面範例應用程式,示範如何在區域網路內用標準 **mDNS/DNS-SD**(RFC 6762/6763)自動探索裝置,並透過 TCP 交握流程(送出連線請求 → 對方確認接受/拒絕)建立一對一連線、傳輸檔案;另外還有一個完全獨立的**影片伺服器**功能,可以把這台裝置變成一個區網內的迷你影片網站,讓其他裝置直接用瀏覽器觀看。

因為裝置探索與交握都採用標準協定,理論上可以與其他平台(例如 Android 端用 `NsdManager` 註冊相同的 service type)互相探索、互相連線。

## 功能特色

### 裝置配對與檔案傳輸

- **自動廣播與探索**:啟動後自動用 mDNS 廣播自己,並持續搜尋區網內其他執行中的裝置;搜尋秒數可在設定頁調整。
- **連線確認交握**:發起連線的一方送出請求後,需等待對方在畫面上按下「接受」或「拒絕」才會建立連線。
- **檔案與資料夾傳輸**:連線後可以按「傳送檔案」/「傳送資料夾」,或直接把檔案/資料夾拖曳到視窗來傳送;對方會跳出確認對話框,接受後顯示進度並可隨時取消。資料夾傳輸會保留子目錄結構,一次選取多個檔案則不會另外建立子資料夾。接收的檔案預設存到 `Downloads` 資料夾,可在設定頁更改。
- **斷線偵測**:任一方關閉連線,或裝置從區網離線,都會自動更新畫面(移除裝置卡片、返回搜尋畫面),不需要手動重新整理。
- **系統匣圖示**:關閉視窗會隱藏到系統匣而不是結束程式,裝置探索與連線功能持續在背景運作;可從系統匣選單重新開啟視窗或結束程式。

### 影片伺服器

- **分享單一影片或整個資料夾**:在「影片」頁籤選擇要分享的影片檔案或裝滿影片的資料夾,這台裝置就會變成一個獨立的影片伺服器 —— 不需要先跟其他裝置配對連線。
- **自動被發現**:透過另一組 mDNS 服務類型廣播,區網內其他裝置的「影片」頁籤會自動列出這台伺服器,點「觀看」就能直接看,不用輸入 IP。
- **像 YouTube 一樣的網站**:伺服器內建一個最小的 HTTP 伺服器,提供的是一個完整的網站(首頁縮圖清單 + 觀看頁),用內嵌瀏覽器(WebView2)開啟即可,不需要額外的播放器軟體 —— 理論上用任何瀏覽器打開該裝置的網址也能看。
  - 影片播放支援 HTTP Range,拖曳進度、快轉/倒轉都是即時的。
  - 觀看頁有自製的播放控制列(播放/暫停、快轉倒轉 10 秒、上一部/下一部、播放速度、音量、全螢幕),圖示皆為內嵌的 Material Icons SVG,不依賴任何線上字型/CDN。
  - 支援自動播放下一部(可關閉)、記住播放進度與音量、鍵盤快捷鍵(空白鍵播放/暫停、方向鍵快轉/調音量、F 全螢幕、M 靜音)。
  - 首頁與觀看頁側邊清單都會顯示影片縮圖(透過 Windows 內建的殼層縮圖功能產生,不需要額外安裝 ffmpeg 之類的工具;格式若沒有對應的縮圖處理常式則顯示預設圖示)。
  - 提供排序選項(檔名、檔案大小、修改時間,各自可切換遞增/遞減),排序方式會套用到首頁清單、側邊清單與上一部/下一部導覽。
  - 瀏覽器的「上一頁」手勢(滑鼠側鍵、Alt+左鍵等)一律導回網站首頁,而不是照瀏覽紀錄跳回上一支看過的影片。
- **支援多人同時觀看**:影片資料透過獨立的 HTTP 連線傳輸,多個裝置可以同時觀看同一支或不同影片,互不影響。

### 共同

- **Material Design UI**:使用 [MaterialDesignThemes](https://github.com/MaterialDesignInXAML/MaterialDesignInXamlToolkit) 打造的介面。
- **導覽列與設定頁**:左側導覽列可在「裝置」「影片」「設定」三個頁面間切換;設定頁可選擇淺色、深色或跟隨系統的顏色主題、調整自動搜尋秒數、更改檔案接收資料夾,設定會儲存在本機。

## 專案結構

| --- | --- |
| `ConnectIt.Wpf` | 主要的 WPF 應用程式 |
| `ConnectIt.Wpf/Services/MdnsDiscoveryService.cs` | 負責 mDNS 裝置廣播與探索;可指定不同的服務類型,裝置配對與影片伺服器各自用一個獨立的實例 |
| `ConnectIt.Wpf/Services/ConnectionService.cs` | 負責 TCP 連線交握(請求/接受/拒絕)、斷線偵測,以及連線建立後的檔案/資料夾傳輸訊框協定 |
| `ConnectIt.Wpf/Services/ThemeService.cs` | 負責套用與儲存淺色/深色/跟隨系統的顏色主題 |
| `ConnectIt.Wpf/Services/FileTransferSettingsService.cs` | 負責儲存接收檔案要存放的資料夾設定 |
| `ConnectIt.Wpf/Services/DiscoverySettingsService.cs` | 負責儲存自動搜尋裝置的秒數設定 |
| `ConnectIt.Wpf/Services/VideoStreamingService.cs` | 影片伺服器本體:自己實作的最小 HTTP 伺服器,提供首頁/觀看頁網站、影片位元組串流(含 Range)、縮圖端點 |
| `ConnectIt.Wpf/Services/VideoLibraryScanner.cs` | 掃描單一影片檔案或資料夾,建立可分享的影片清單(manifest) |
| `ConnectIt.Wpf/Services/VideoThumbnailGenerator.cs` | 用 Windows 殼層縮圖 API 產生影片縮圖 |
| `ConnectIt.Wpf/Models/DiscoveredDevice.cs` | 探索到的裝置/影片伺服器共用的資料模型 |
| `ConnectIt.Tests` | 使用 xUnit 撰寫的單元測試,涵蓋連線交握流程、裝置模型、檔案/資料夾傳輸,以及影片伺服器的 HTTP 路由與網頁內容 |

## 需求環境

- Windows 10/11
- [.NET 10 SDK](https://dotnet.microsoft.com/) (`net10.0-windows`)
- [Microsoft Edge WebView2 執行階段](https://developer.microsoft.com/microsoft-edge/webview2/)(觀看影片伺服器網站用;Windows 11 通常已內建,Windows 10 若尚未安裝會自動提示安裝 Evergreen 執行階段)

## 建置與執行

```powershell
# 還原套件並建置
dotnet build

# 執行應用程式
dotnet run --project ConnectIt.Wpf
```

啟動兩個(或以上)執行個體(同一台機器上開兩個視窗,或在同一區網的兩台機器上各執行一份),即可在「裝置」頁看到彼此並互相連線傳檔案,或在「影片」頁分享/觀看影片。

```powershell
dotnet test
```

## 運作原理簡述

### 裝置配對與檔案傳輸

1. 應用程式啟動時,`ConnectionService` 開始監聽一個 TCP 連接埠,`MdnsDiscoveryService` 將此連接埠與裝置名稱透過 mDNS 廣播出去,同時開始搜尋網路上其他裝置。
2. 使用者在裝置清單中點選欲連線的裝置後,發起端會建立 TCP 連線並送出 `request` 訊息。
3. 被連線的一方跳出確認對話框,使用者按下「接受」或「拒絕」後回傳 `accept`/`reject` 訊息。
4. 若接受,雙方各自進入已連線畫面,並開始監控連線狀態;任一方關閉連線都會通知另一方並返回裝置搜尋畫面。
5. 連線建立後,同一個 TCP socket 改用一個簡單的長度前綴訊框協定傳輸資料(控制訊息或檔案內容區塊)。單一檔案走 `file-offer` → `file-accept`/`file-reject` → 分塊傳送 → `file-complete` 交握;資料夾/多檔案則是先送出 `folder-offer`,對方接受後底下每個檔案沿用同一套檔案交握自動依序傳送,任一方也可以隨時取消整個傳輸。

### 影片伺服器

1. 使用者在「影片」頁選擇要分享的影片或資料夾後,`VideoStreamingService` 掃描出影片清單,開啟一個綁在區網網卡位址上的 TCP 監聽器(自己解析/組出最小的 HTTP/1.1 訊息,刻意不用 `HttpListener`,避免非系統管理員權限時的存取限制),並透過另一組 mDNS 服務類型把「這裡有個影片伺服器」廣播出去。
2. 其他裝置的「影片」頁自動列出這台伺服器;點「觀看」會用內嵌瀏覽器開啟該伺服器的首頁網址,不需要額外的配對/確認流程。
3. 首頁、觀看頁與影片位元組本身都是同一個 HTTP 伺服器提供的資源(`/`、`/watch?v=`、`/media/`、`/thumbnail/`),每個請求各自獨立處理,天然支援多人同時觀看與拖曳進度(HTTP Range)。
4. 觀看端網頁本身(HTML/CSS/JavaScript)負責播放器介面、排序、上一頁攔截等所有互動邏輯,完全不依賴外部 CDN 或字型,確保沒有網際網路連線時也能正常運作。
